# 毕设五大核心功能

本版聚焦简历诊断、岗位匹配、AI 学习路径、AI 模拟面试、RAG 知识问答。岗位发布与账号、知识库管理是配套功能。投递、企业初筛、通知、审计、部署向导等辅助前端页面下线，原后端接口与历史数据保留。

## 数据与启动

- 持久化运行使用 MySQL 和 Redis；`scripts/start-local-dev.ps1` 自动读取 `.env`，启用账号、学生资料及 AI 核心记录持久化。业务服务继续可独立启动。
- `-DemoMode` 使用内存、明确初始化演示内容，重启会丢失本次数据。
- `-SeedDemoData` 仅开启演示种子，不关闭数据库存储；初始化已有数据时不覆盖用户修改。普通启动不自动添加样例。
- 无样例账号时，设置 `BOOTSTRAP_ADMIN_PASSWORD` 以创建首个 `admin`。管理员可以创建学生与企业账号；学生和企业也可通过现有注册 API 注册。
- 本地 MySQL 端口读取 `MYSQL_HOST_PORT`，Redis 端口读取 `REDIS_HOST_PORT` / `SPRING_DATA_REDIS_PORT`。不要覆盖其他项目的数据库或 Redis。
- 账号使用 `auth_account`，学生资料使用 `student_profile`。新增核心业务表采用兼容性创建，旧记录不清空。

## 演示顺序

1. 企业登录，发布包含明确技能要求的岗位。
2. 学生上传文本型 PDF/DOCX 简历，核对并修正提取的资料，选择目标岗位后诊断。
3. 执行岗位匹配，查看技能覆盖率、已具备技能和差距。
4. 使用该匹配记录生成学习路径，设置周期与每周时间，完成一项任务并填写反馈。
5. 发起模拟面试，按顺序作答并生成报告；使用报告中的薄弱项调整学习计划，查看旧版本与完成记录。
6. 管理员上传知识资料并设置访问权限；学生提问、展开引用原文，验证资料来源。
7. 重启服务后重新登录，检查简历历史、学习进度及面试会话仍可恢复。

建议分别使用 Java、前端和一个非技术岗位。模型调用失败会显示规则或演示来源；数据库写入失败不作为保存成功。扫描型简历需先转成可提取正文的文档，本版不包含 OCR、语音或视频面试。

学习计划允许每周 2–40 小时、1–24 周，面试允许 1–8 道主问题。旧版本只读；模型无法生成有效的新计划时，调整请求失败并保留原计划。

## 验证命令

```powershell
cd backend
mvn -s settings.xml.example test
cd ../frontend
npm.cmd run test:unit
npm.cmd run build
$env:E2E_BASE_URL = 'http://127.0.0.1:5173'
npm.cmd run test:e2e
```

接口与字段以 `docs/api.md` 和服务 OpenAPI 为准。浏览器验证须使用真实登录令牌，不手工伪造用户会话。数据库重启恢复和真实模型调用需在持久化运行实例中额外验证，单元测试通过并不替代这些检查。

启动持久化服务并初始化演示管理员后，在仓库根目录执行以下集成检查（会创建独立测试账号、岗位、简历和知识资料，并调用 `.env` 已配置的模型）：

```powershell
node scripts/check-core-mvp.cjs
# 重启服务后，不重新初始化样例，再执行：
node scripts/check-core-mvp.cjs --verify-restart
```

检查涵盖 Java、前端、运营岗位技能匹配、跨学生权限、诊断历史、学习进度与重规划、面试报告、知识引用与文件导入。结果编号保存到已忽略的 `logs/core-mvp-verification.json`，不保存登录令牌。默认验证管理员为演示账号，可通过 `MVP_ADMIN_USER` / `MVP_ADMIN_PASSWORD` 覆盖。

如果本机已存在独立创建的 `recruit-mysql` 容器，使用 `docker start recruit-mysql` 恢复它，再执行 `docker compose up -d redis`；不要为解决 Compose 同名容器冲突而删除数据库卷。

## 五模块使用与可靠性优化（2026-09-18）

- 简历诊断：上传前校验格式、空文件与 10 MB 大小限制；结构化资料修改后需先保存再诊断，真实变更会使当前诊断失效，历史报告保留。无变更保存保留已有诊断。未提交资料按账号和简历隔离保存到当前标签页的草稿中，支持页面切换与刷新；删除前确认。
- 岗位匹配：支持关键词、城市和技能组合筛选，展示技能证据与建议，历史记录可恢复并带入学习计划或面试。技能快照与当前资料不一致时提示重新匹配，避免沿用过期差距。未配置技能要求显示“匹配依据不足”，已关闭岗位禁止新匹配；内存与数据库列表均按新记录优先展示。
- AI 学习路径：可选择简历和岗位来源、查看不同版本、逐项保存进度与复盘备注；单项失败保留输入并可重试，保存不清除其他任务草稿。后端采用快照条件写入和有限重试，避免并发任务更新互相覆盖；重规划引用的面试必须属于相同目标、简历、岗位和匹配记录。
- 模拟面试：明确本次目标岗位，按顺序作答，已提交答案和完成会话只读。未提交回答按账号和会话隔离，在当前浏览器标签页保留；保存后恢复服务端答案，全部答题完成后生成报告并展示逐题反馈。并发保存和重复完成不会覆盖已完成报告。
- RAG 知识问答：默认仅检索，可切换 AI 回答；优先展示检索结果，回答失败仍保留可用资料。提供引用展开、最近查询和失败重试。模型返回空内容或异常时明确使用本地检索摘要，不把服务异常内容展示为 AI 答案。

草稿使用 `sessionStorage`，关闭标签页后不保证恢复；正式保存的简历、学习任务和面试答案存入后端。浏览器草稿不替代“保存资料”或“保存回答”。界面继续沿用薄荷绿与深绿工作台布局。
