# v3.4 Student AI Career Planning and Admin Dashboard Enhancement

## Scope

- Added student AI resume rewrite capability through `POST /api/ai/resume/rewrite`.
- Added student AI career planning capability through `POST /api/ai/career/plan`.
- Extended the admin dashboard response with `interviewRate`, `offerRate`, `activeStudentCount`, `highPotentialCandidateCount`, `weeklyDeliveryTrend`, `skillDemandTop`, `conversionFunnel`, and `riskAlerts`.
- Added a student AI job-search planning page covering resume rewrite, career roadmap, skill gaps, weekly actions, portfolio tasks, and interview focus.
- Enhanced the admin data screen to show conversion metrics, weekly delivery trends, skill demand, funnel stages, active/high-potential students, and risk alerts.

## API Contracts

- `POST /api/ai/resume/rewrite`
  - Request: `studentId`, `resumeId`, `targetRole`, `resumeSummary`, `skills`, and `projects`.
  - Response: `ResumeRewriteResponse` with `studentId`, `resumeId`, `targetRole`, `improvedSummary`, `rewrittenProjects`, `keywordSuggestions`, `missingEvidence`, `actionChecklist`, and `mocked`.
  - Gateway-injected `X-User-Role=STUDENT` and `X-User-Id` take precedence over the request body `studentId`.

- `POST /api/ai/career/plan`
  - Request: `studentId`, `targetRole`, `skills`, `interests`, `resumeSummary`, and `timeframeWeeks`.
  - Response: `CareerPlanResponse` with `studentId`, `targetRole`, `readinessScore`, `summary`, `milestones`, `skillGaps`, `weeklyActions`, `portfolioTasks`, `interviewFocus`, and `mocked`.
  - Each `milestones` item contains `title`, `timeframe`, and `goals`.
  - Gateway-injected `X-User-Role=STUDENT` and `X-User-Id` take precedence over the request body `studentId`.

- `GET /api/admin/dashboard`
  - Existing fields remain unchanged: `studentCount`, `companyCount`, `jobCount`, `deliveryCount`, `averageMatchScore`, `deliveryStatusCounts`, and `pendingDeliveryCount`.
  - New fields:
    - `interviewRate`: integer percentage of deliveries that reached interview or offer.
    - `offerRate`: integer percentage of deliveries that reached offer.
    - `activeStudentCount`: active student count for the current dashboard window.
    - `highPotentialCandidateCount`: count of candidates suitable for priority guidance or recommendation.
    - `weeklyDeliveryTrend`: trend points with `label`, `deliveryCount`, `interviewCount`, and `offerCount`.
    - `skillDemandTop`: skill demand entries with `skill`, `jobCount`, `matchedStudentCount`, and `demandScore`.
    - `conversionFunnel`: funnel stages with `stage`, `label`, `count`, and `conversionRate`.
    - `riskAlerts`: readable risk alerts for employment-office follow-up.

## Frontend Notes

- Student side adds an AI job-search planning page that connects resume rewrite and career planning with the current student identity, uploaded resume summary, target role, skills, projects, and interests.
- The planning page should keep deterministic demo fallback data when no gateway or AI proxy is configured, matching existing frontend fallback behavior.
- Admin side dashboard enhancements should render the new metrics as dense management information: KPI cards, trend chart, skill demand ranking, funnel, and risk alert list.

## Safety and Fallback

- All public API responses continue to use `ApiResponse<T>`.
- AI credentials remain environment-driven; documentation and frontend examples must not hardcode real provider keys.
- Resume rewrite and career plan responses must not expose API keys, tokens, raw prompts, full resume text, or hidden system instructions.
- When DashScope is not configured or a model call fails, both AI endpoints return deterministic fallback data with `mocked=true`.
