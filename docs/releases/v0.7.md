# v0.7 AI Candidate Screening History

## Scope

- AI 候选人初筛结果在 `ai-service` 内存中保存为历史记录。
- 新增筛选历史查询接口，支持按 `companyId` 和 `deliveryId` 过滤。
- 企业端进入页面自动加载本企业筛选历史，点击 `AI 筛选` 后生成新记录并刷新列表。
- 离线演示模式仍可使用本地 fallback 数据，确保没有 AI 服务或网关时前端可展示历史面板。

## API

- `POST /api/ai/candidates/screen`
  - 请求体新增可选 `companyId`，缺省为 `C001`。
  - 生成结果后写入当前 AI 服务进程内存。
- `GET /api/ai/candidates/screenings?companyId=C001&deliveryId=D001`
  - `companyId`、`deliveryId` 均可选。
  - 返回 `CandidateScreenRecord[]`。
  - 字段：`screeningId`、`companyId`、`deliveryId`、`studentId`、`jobId`、`score`、`recommendation`、`strengths`、`risks`、`interviewQuestions`、`nextActions`、`mocked`、`createdAt`。

## Verification

```powershell
cd backend
mvn -s settings.xml.example -pl common,ai-service -am test

cd ../frontend
npm run test:unit
npm run build
```

Runtime validation:

- Start the updated `ai-service` on a free local port, for example `8116`.
- Start Vite with `VITE_AI_PROXY_TARGET=http://127.0.0.1:8116`.
- Login as `company`, open 企业端, confirm existing screening records load, click `AI 筛选`, and confirm a new history card appears.

## Notes

- This version intentionally keeps screening history in memory to preserve the runnable MVP.
- The next persistence step is moving `CandidateScreenRecord` into MySQL with optional Redis caching for recent enterprise history.
