# v3.8 Notifications, Interview Scheduling, RAG, MQ, and Load Smoke

## Scope

- Added notification center APIs and UI modules for student and company users.
- Added interview scheduling APIs and UI modules. Companies can schedule interviews from delivery review; students can confirm or decline proposed schedules.
- Added a local RAG-style knowledge base in `ai-service`, including seeded documents, admin document creation, role-aware document listing, and role-aware retrieval.
- Reused the existing `delivery-events` RocketMQ publisher for notification and interview lifecycle events.
- Added `scripts/run-load-smoke.ps1` for lightweight Gateway performance smoke testing.

## Services

- `delivery-service` remains on port `8107`.
  - Health: `/actuator/health`
  - OpenAPI UI: `/swagger-ui.html`
  - New API groups: `/api/notifications/**`, `/api/interviews/schedules/**`
- `ai-service` remains on port `8106`.
  - Health: `/actuator/health`
  - OpenAPI UI: `/swagger-ui.html`
  - New API group: `/api/ai/knowledge/**`
- `gateway-service` remains on port `8080`.
  - Routes `/api/notifications/**` and `/api/interviews/schedules/**` to `delivery-service`.
  - Routes `/api/ai/knowledge/**` to `ai-service`.

## Verification

## Load Smoke

Run against local Gateway or VM1 Gateway:

```powershell
$env:THREE_VM_DEMO_PASSWORD = Read-Host "Demo password"
.\scripts\run-load-smoke.ps1 -BaseUrl http://192.168.6.130:8080 -Users 3 -Iterations 3 -TimeoutSeconds 10
```

The script logs in `student`, `company`, and `admin`, calls core read endpoints plus the new RAG and notification probes, and writes `reports/deploy/load-smoke-<timestamp>.md`. Demo passwords and bearer tokens are not written to the console or report.

China-accessible mirrors remain inherited from the existing Maven, npm, and Docker mirror configuration; this release does not add new external package sources.
