# v3.1 AI Screening Task Recovery

## Scope

- Added task-level async screening operations for company users.
- Added single-task refresh support through `GET /api/ai/candidates/screen/tasks/{taskId}`.
- Added failed-task retry support through `POST /api/ai/candidates/screen/tasks/{taskId}/retry`.
- Updated frontend fallback data with a failed demo task so retry can be demonstrated offline.
- Updated the company AI screening page with compact refresh and retry controls.

## APIs

- `GET /api/ai/candidates/screen/tasks/{taskId}?companyId=C001`
  - Returns `ApiResponse<CandidateScreenTask>`.
  - Company gateway identity overrides the query `companyId`.

- `POST /api/ai/candidates/screen/tasks/{taskId}/retry?companyId=C001`
  - Returns `ApiResponse<CandidateScreenTask>`.
  - Only `FAILED` tasks can be retried.
  - Successful retry enqueues a new task and keeps the original failed task.

## Frontend Behavior

- Each task card has a compact single-task refresh action.
- Failed task cards also show a retry action.
- Retry fallback creates a deterministic pending demo task when no backend or AI proxy is configured.
- Task metadata and action buttons wrap safely on mobile.
