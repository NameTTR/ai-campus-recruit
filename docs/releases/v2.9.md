# v2.9 Admin Audit Data Center

## Scope

- Added the admin navigation entry `/admin/audit`.
- Added the admin audit data center for students, jobs, deliveries, AI candidate screening, and AI interview records.
- Added backend and frontend contracts for `GET /api/admin/audit/overview` and `POST /api/admin/audit/export`.
- Added Gateway/RBAC permission coverage for `admin:audit:read` and `admin:audit:export`.
- Documented the API contract, fallback behavior, permissions, and redaction rules.

## Frontend

- `/admin/audit` shows audit filters, summary metrics, cross-service audit rows, warnings, and export task metadata.
- Filters include `keyword`, `entityType`, `studentId`, `companyId`, `jobId`, and `limit`.
- Desktop uses a dense audit table; mobile switches to audit cards so long ids, summaries, tags, and URLs do not overflow.
- Demo fallback remains deterministic when no `VITE_API_BASE_URL` or `VITE_API_PROXY_TARGET` is configured.

## API Contract

- `GET /api/admin/audit/overview`
  - Response: `ApiResponse<AdminAuditOverview>`.
  - Query: `keyword`, `entityType`, `studentId`, `companyId`, `jobId`, `limit`.
  - Entity types: `STUDENT`, `JOB`, `DELIVERY`, `AI_SCREENING`, `AI_INTERVIEW`.
  - Expected permission: `admin:audit:read`.

- `POST /api/admin/audit/export`
  - Response: `ApiResponse<AdminAuditExportResult>`.
  - Body: overview filters plus `format=CSV`.
  - Expected permission: `admin:audit:export`.

- Responses and exports must redact API keys, tokens, raw AI prompts, full resume text, password hashes, and other secrets.
