# v0.9 Three-VM Distributed Deployment

## Scope

- 新增三台 Ubuntu 虚拟机分布式部署拓扑。
- VM1 运行 Nacos、`gateway-service` 和前端 Nginx。
- VM2 运行业务服务：`auth-service`、`user-service`、`resume-service`、`job-service`、`match-service`、`delivery-service`。
- VM3 运行 `ai-service`、MySQL、Redis、MinIO 和 RocketMQ。
- Gateway 通过 VM2/VM3 内网 IP 转发到各业务服务，避免三机 Compose 网络无法互通的问题。
- 前端 Nginx 改为运行时模板，通过 `GATEWAY_UPSTREAM` 生成 `/api/*` 代理目标。
- 三机部署文档、Compose 文件和示例环境变量均使用国内可用镜像源或下载源。

## Topology

| VM | Services |
| --- | --- |
| VM1 | Nacos, `gateway-service`, frontend Nginx |
| VM2 | `auth-service`, `user-service`, `resume-service`, `job-service`, `match-service`, `delivery-service` |
| VM3 | `ai-service`, MySQL, Redis, MinIO, RocketMQ |

Startup order:

1. VM1 starts Nacos.
2. VM3 starts MySQL, Redis, MinIO and RocketMQ.
3. VM3 starts `ai-service`.
4. VM2 starts business services.
5. VM1 starts `gateway-service` and frontend Nginx.

## Configuration

- All VMs copy `deploy/three-vm.env.example` to `deploy/three-vm.env`.
- `VM1_HOST`, `VM2_HOST` and `VM3_HOST` must be set to reachable intranet IP addresses.
- `DASHSCOPE_API_KEY` remains optional; when unset, AI endpoints use mock fallback.
- `AI_SCREENING_PERSISTENCE_ENABLED=true` enables MySQL persistence and Redis cache for AI candidate screening history.
- Do not commit real `.env`, `deploy/three-vm.env` or API keys.
