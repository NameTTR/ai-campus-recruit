# v3.3 One-Command Deployment and Distributed AI Flow

## Scope

- Added `scripts/deploy-three-vm.ps1` as the Windows host entry for one-command three-VM deployment.
- Added `scripts/check-distributed-ai-flow.ps1` to verify the end-to-end flow from delivery creation to RocketMQ event publishing, AI event consumption, async screening task completion, and real DashScope candidate screening.
- Fixed local dev startup by replacing the broken parent-POM `spring-boot:run` flow with a build-once, run-jar startup script.
- Fixed RocketMQ broker advertisement for cross-VM clients by generating `brokerIP1=${VM3_HOST}` inside `deploy/docker-compose.vm3.yml`.
- Fixed the deploy script SSH command binding by using `-RemoteCommand` consistently, and resolved VMX files from VM directories to avoid depending on a non-ASCII VMX filename literal.
- The three-VM deploy script removes stale `recruit-*` containers by default, which is required when VM2 and VM3 were cloned from VM1 and still have VM1 Nacos/Gateway containers occupying ports.

## Deployment Entry

Interactive SSH password mode:

```powershell
.\scripts\deploy-three-vm.ps1 -SshUser ubuntu
```

SSH key mode:

```powershell
.\scripts\deploy-three-vm.ps1 -SshUser ubuntu -IdentityFile $HOME\.ssh\id_ed25519
```

Non-interactive validation mode:

```powershell
.\scripts\deploy-three-vm.ps1 -SshUser ubuntu -IdentityFile $HOME\.ssh\id_ed25519 -NonInteractive
```

The script resolves VM IPs with `vmrun`, builds a temporary deployment env without printing secrets, uploads the committed Git revision to each VM, starts VM3 -> VM2 -> VM1, then runs the health and distributed AI flow checks.

Observed:

- `ubuntu`, `hadoop`, and `gjw` SSH key logins returned `Permission denied (publickey,password)`.
- `vmrun` guest-operation login attempts with common local lab credentials were rejected by the guest OS.
- VM2 and VM3 expose stale VM1-like ports (`8080`, `8848`), which the v3.3 deployment script is designed to clean after SSH access is available.

To finish real three-VM deployment, run `scripts/deploy-three-vm.ps1` in a visible PowerShell window and enter the VM SSH password when prompted, or install the Windows host public SSH key into the VM users' `authorized_keys`.
