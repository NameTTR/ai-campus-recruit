# v1.9 Resume Persistence and Cache

## Scope

- `resume-service` supports optional MySQL persistence for resume summaries and extracted resume text.
- The default local demo still uses in-memory storage when `RESUME_PERSISTENCE_ENABLED=false`.
- Resume detail uses Redis cache-aside when Redis is available.
- Uploading or analyzing a resume refreshes the related detail cache after a successful database write.
- Runtime database or Redis failures are logged and degraded so upload, detail and AI diagnosis remain demo-usable.
- Single-machine Docker Compose and three-VM Compose can enable resume persistence against MySQL/Redis while MinIO keeps storing resume objects.

## Configuration

- `RESUME_PERSISTENCE_ENABLED`
  - Default: `false`
  - Docker Compose default: `true`
- `SPRING_DATASOURCE_URL`
  - Example: `jdbc:mysql://mysql:3306/ai_campus_recruit?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false`
- `SPRING_DATASOURCE_USERNAME`
- `SPRING_DATASOURCE_PASSWORD`
- `SPRING_DATA_REDIS_HOST`
- `SPRING_DATA_REDIS_PORT`
- `RESUME_CACHE_TTL`
  - Default: `10m`
- `RESUME_CACHE_KEY_PREFIX`
  - Default: `resume:summaries`
- `RESUME_DB_HEALTH_ENABLED`
  - Default: `false`
- `RESUME_REDIS_HEALTH_ENABLED`
  - Default: `false`

## Redis Keys

- `resume:summaries:detail:{resumeId}`

When a resume is uploaded or analyzed, the service refreshes the detail cache for that resume. If a database write fails, the service falls back to the in-memory store and evicts the possibly stale cache entry.

## Fallback

- Persistence disabled: use in-memory resume summaries and extracted text.
- Persistence enabled but datasource or mapper missing: use in-memory resume summaries and extracted text.
- Database read/write fails at runtime: fall back to in-memory summaries and extracted text for that operation.
- Redis read/write/delete fails: log and continue with database query or save.
- DB and Redis health contributors are disabled by default so a missing local MySQL/Redis instance does not mark the demo service down.

## Verification

```powershell
cd backend
mvn -s settings.xml.example -pl common,resume-service -am test
mvn -s settings.xml.example test
```

Runtime verification through the gateway:

```powershell
POST http://localhost:8080/api/resumes/upload
GET  http://localhost:8080/api/resumes/{id}
POST http://localhost:8080/api/resumes/{id}/analyze
```

After restarting `resume-service`, detail and analysis should still return the uploaded resume when persistence is enabled.
