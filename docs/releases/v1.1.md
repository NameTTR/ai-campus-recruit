# v1.1 MinIO Resume Object Storage

## Scope

- `resume-service` 接入 MinIO Java SDK。
- 简历上传后生成对象 key，并在 `ResumeSummary` 中返回 `objectKey`、`storageProvider`、`storageStatus`。
- 默认本地开发不开启对象存储，返回 `local-demo/SKIPPED`，保证无 MinIO 时仍可演示。
- Docker Compose 和三机部署开启对象存储，`resume-service` 指向 MinIO。
- MinIO 写入失败时返回 `minio/FAILED`，上传接口仍返回统一 `ApiResponse<ResumeSummary>`，不阻断简历诊断演示。
- 学生端简历卡片显示对象存储 provider 和状态。

## Configuration

- `RESUME_OBJECT_STORAGE_ENABLED`
  - 本地默认：`false`
  - Docker Compose / 三机部署默认：`true`
- `MINIO_ENDPOINT`
  - 单机 Compose：`http://minio:9000`
  - 三机 VM2：`http://${VM3_HOST}:9000`
- `MINIO_ACCESS_KEY`
- `MINIO_SECRET_KEY`
- `MINIO_BUCKET`
  - 默认：`resumes`

Do not commit real MinIO credentials.

## API Impact

`POST /api/resumes/upload` 和 `GET /api/resumes/{id}` 返回的 `ResumeSummary` 新增：

- `objectKey`
- `storageProvider`
- `storageStatus`

示例状态：

- `SEEDED`：内置演示简历。
- `SKIPPED`：对象存储未开启，本地演示跳过写入。
- `STORED`：文件已写入 MinIO。
- `FAILED`：尝试写入 MinIO 失败，主流程降级继续。
